# kuangjia-chaijie · 框架主题深度拆解工作流

[English](./README.md) | 中文

> **这个 skill 不输出文章，它输出"完整、可口头复述的理解"。**
> 输入：一个框架/代码库 + 一个主题词　→　产出：4（+1 可选）份结构化 markdown。
> 写文章是 skill 结束之后的事。

给要做技术分享 / 写技术文章 / 团队讲座的人用：在动笔之前，先把一个跨多模块的主题**完整、清晰、不漏**地搞清楚。

---

## 它解决什么问题

读框架源码最容易犯三种错：

1. **猜**——用"通常""一般来说""按惯例"拿训练语料里的通用模式填空，而那很可能跟当前项目的真实实现不同。
2. **漏**——主题跨多个模块，按当前认知自顶向下扫，藏在大文件中段或后台路径里的子系统根本抓不到。
3. **飘**——浅读出浅结论，自己回头自查时眼睛会跳过已经写过的地方，错误一路留到最后。

本 skill 用一套 agentic 流水线对治：**自顶向下（项目心智模型扫描）+ 自底向上（符号反向追踪）双路并用**，关键节点强制人在回路确认范围，每个阶段有硬退出标准，每阶段产物交给**干净上下文的子代理**对照源码交叉验证。

---

## 适用 / 不适用

✅ 适用
- 准备写技术分享 / 公众号 / 团队讲座，但还没完全摸清主题
- 主题跨多个模块（不是单文件能解释的）
- 想"完整不漏"地理解某个子系统

❌ 不适用
- 单文件、单函数问题 → 直接 Read / Grep
- 调试具体 bug → 用 debugging skill
- 设计新功能 → 用 brainstorming → writing-plans

## 流水线（4 阶段 + 1 可选）

| 阶段 | 做什么 | 产出 | 退出门槛（节选） |
|---|---|---|---|
| **0 主题播种** | 把模糊主题词落成「种子卡」 | `00-seed.md` | 关键词 ≥5、显式排除 ≥2 |
| **1 全景扫描 (A+B)** | 心智模型 + 符号热力图 + 交叉对照 + 全景图 + 反向覆盖 + 盲点检阅 | `01-*.md` | 子系统 5–9 个、≥2 张 Mermaid、子代理验证过、用户拍板 |
| **2 逐子系统深挖** | 每个子系统填「七要素卡 + 设计取舍 + 回顾」 | `02-{slug}.md`（每子系统一份） | 每卡 10 块全填、生命周期图、子代理验证过 |
| **3 重新归一** | v0→v1、架构总图、跨系统模式、跨卡矛盾、上游回填 | `03-synthesis.md` | 一句话本质、≥2 跨系统模式、矛盾显式决议、回填表逐行处置 |
| **4 演进溯源（可选）** | 按兴趣挑子系统，用漏斗式 git 考古看「它怎么迭代成现在这样」 | `04-evolution-{slug}.md` | 时间线图 + 拐点带 commit-hash + why、稳定性标注 |

## 四条核心原则

1. **不猜 → 先 Read → 再问**：所有结论必须有依据（读到的代码/文档/数据，或用户明确告知）。出现"通常/一般/应该/大概率"立刻停下，要么补 Read 找依据，要么标 `[待澄清: ...]`。
2. **可视化强制**：纯文字 + 表格不算合格产出，每阶段至少一张 Mermaid 图——画图是发现盲区最高效的工具，画不出来的连线就是真盲区。
3. **干净上下文子代理验证**：每阶段产物交给"从没见过这张卡"的子代理对照源码逐条核对。同上下文 = 同盲区，主代理自验证等于没验证。
4. **带反馈的循环，不是单向管道**：每完成一个阶段回头检查上游产物，发现错漏走 Amend 规则（小修直接改、结构修订记 amendments、抽象层变化进 v0→v1）。

## 安装

### 方式一：插件市场（推荐）

在 Claude Code 中运行：

```bash
/plugin marketplace add eiaao/kuangjia-chaijie
```

然后选择 **Browse and install plugins** → `kuangjia-chaijie` → Install。

### 方式二：手动安装

把 skill 目录拷到 Claude Code 的 skills 目录：

```bash
git clone https://github.com/eiaao/kuangjia-chaijie.git
cp -r kuangjia-chaijie/skills/kuangjia-chaijie ~/.claude/skills/
```

---

## 使用

直接对 Claude 说出你的主题，例如：

- 「我想深入拆解 Hermes 框架的记忆架构」
- 「帮我理清 LangChain 的工具调用机制」
- 「我要写一篇关于 XX 框架某部分的文章，先帮我搞清楚」
- 「先给我把 XX 的全景图整出来」

skill 会从阶段 0 开始，在关键节点停下来等你确认范围。产物默认落在项目根的 `notes/kuangjia-chaijie/{topic-slug}/`。

## 目录结构

```
kuangjia-chaijie/
├── .claude-plugin/marketplace.json   # 插件市场清单
├── skills/kuangjia-chaijie/
│   ├── SKILL.md                      # 工作流主体
│   └── assets/
│       ├── build_view.py             # 把产物 .md 渲染成单页 HTML 视图
│       └── template.html             # HTML 视图模板
├── README.md                         # 英文说明
└── README.zh.md                      # 中文说明（本文件）
```

`assets/build_view.py` 把每阶段的 markdown 产物聚合渲染成可交互的单页 `view.html`（markdown 仍是真相源，HTML 只是 view 层，已在 `.gitignore` 中忽略）。
